# 开放世界设计方案 · 《无双 · 群雄》

> 状态：草案 v0.2（2026-11-22，已定：首图虎牢关—洛阳；马战为核心战斗之一；先做 M0）
> 范围：在现有《无双 · 虎牢关》（`demos/index-webgpu.html`）基础上，做一款「荒野大镖客式探索 + 无双式割草」的三国开放世界。
> 约束：**放开单文件约束**——允许多文件工程、外部模型/动画/地图数据、构建工具。

---

## 0. 一句话定位

**骑马走在东汉末年的中原大地上：远处有村庄炊烟、官道商队、山间流寇；撞上一场仗，就地切进千人割草。**

荒野大镖客给的是「世界在你不在时也在运转」的生活感；无双给的是「一人破万军」的爽感。我们要的是两者的接口：**探索产生遭遇，遭遇升级为战役，战役改变世界。**

### 设计支柱（所有取舍的依据）

| # | 支柱 | 含义 | 反例（不做） |
|---|---|---|---|
| P1 | **世界自己会动** | 村民、商队、巡逻、流寇按日程活动，玩家不在也在推进 | 静态 NPC 站桩等任务 |
| P2 | **路上就有事** | 从 A 到 B 的路上平均每 60–90 秒有一个可选事件 | 大片空地只是赶路 |
| P3 | **割草是高潮，不是日常** | 千人战只在「战役」里出现；平时是小规模遭遇 | 满地图都是 60 个兵 |
| P4 | **选择有后果** | 救不救村子、帮哪方据点，会改变地区势力与后续事件 | 支线做完就清零 |
| P5 | **一眼是三国** | 地貌、建筑、服饰、旗号、天气都有时代感 | 通用奇幻素材 |

## 1. 为什么现在的版本「不好玩」（复盘）

做开放世界之前，先承认竞技场版的问题，否则会原样带进新游戏：

1. **技巧收益太低**：机器人实测「连点 J」35.5 击破 vs 「连段技巧」45.5，只差 28%。
2. **没有威胁**：同时出手的敌兵上限 `MAX_TOKENS = 2`，60 人围着也只有 2 人在打。
3. **没有目标与选择**：一局就是 刷兵 → 华雄 → 吕布 → 结算。
4. **打击感被修 bug 削弱**：轻击 heavy 误判修正后，顿帧/震屏/击退整体变小。
5. **千人军阵只是背景**：远景兵不冲锋、不可交战。

**结论**：开放世界解决的是 3 和 5（目标、规模）；1、2、4 是战斗手感问题，必须在 M0 先修，否则世界再大也是空的。

## 2. 核心循环

```
          ┌──────────── 探索（骑马/步行）────────────┐
          │                                          │
   发现地点/事件 ──► 选择介入？ ──否──► 继续赶路       │
          │            │是                            │
          │            ▼                              │
          │      小遭遇（5–30 人）◄──升级── 战役（数百至上千人）
          │            │                              │
          │            ▼                              │
          │      奖励：钱粮 / 声望 / 装备 / 情报         │
          │            │                              │
          └──── 世界状态变化（势力/据点/村庄）◄────────┘
```

**三层时间尺度**

| 尺度 | 时长 | 内容 |
|---|---|---|
| 秒 | 1–30 s | 战斗手感：连段、闪避、弹反、无双 |
| 分钟 | 2–15 min | 一次事件/遭遇/据点战 |
| 小时 | 1–3 h | 一个地区的势力变化 + 一章主线 |

## 3. 世界

### 3.1 地图

- **尺寸**：第一张图 **4 km × 4 km**（司隶 · 虎牢关—洛阳一带，艺术化压缩）。骑马横穿约 3–4 分钟。
- **地貌分区**（每区有独立配色、植被、天气倾向）：

| 区域 | 地貌 | 代表地点 | 主要事件类型 |
|---|---|---|---|
| 虎牢关 | 关隘、峡谷、土塬 | 虎牢关（现有关楼）、汜水 | 关隘攻防、伏击 |
| 洛阳郊野 | 平原、麦田、官道 | 洛阳外城、驿站、集市 | 商队、流民、巡逻 |
| 邙山 | 丘陵、松林、古墓 | 山寨、古陵 | 山贼、夜袭、寻宝 |
| 河畔 | 黄河滩地、渡口、芦苇 | 孟津渡、渔村 | 渡河战、水寇 |

- **路网**：官道（宽、快、有驿站）→ 乡道 → 山径；骑马在官道上速度 +30%。
- **地标可视距离 ≥ 1.5 km**：关楼、城墙、烽火台、寺塔，用于导航（参考 RDR2 的「看见就能去」）。

### 3.2 地点类型

| 类型 | 数量（首图） | 功能 |
|---|---|---|
| 城池 | 1（洛阳外城） | 商店、铁匠、任务、主线枢纽 |
| 关隘 | 2（虎牢、汜水） | 战役发生地 |
| 村庄 | 5–6 | 补给、村民委托、可被劫掠/解救 |
| 营寨/据点 | 8–10 | 可占领，决定地区势力 |
| 驿站 | 3–4 | 快速旅行点、换马、情报 |
| 野外兴趣点 | 20+ | 古墓、营火、废弃战场、隐士、猎场 |

### 3.3 势力

| 势力 | 行为 |
|---|---|
| 讨董联军（玩家阵营） | 据点会补兵、派巡逻，玩家声望高时提供援军 |
| 董卓军 | 主要敌对，控制关隘与多数据点，定期出兵 |
| 黄巾余党/山贼 | 劫掠村庄与商队，在邙山、河畔活动 |
| 百姓 | 村民、商队、流民；被保护或被劫掠会改变区域繁荣 |

**区域控制值**：每个区域 0–100（联军 ↔ 董卓），由据点归属与事件结果驱动，影响巡逻密度、物价、事件池、天气旗号颜色。

## 4. 系统设计

### 4.1 移动

- **步行**：沿用现有角色控制。
- **骑马**（新增，核心）：
  - 呼马（按 `H`）：马从附近跑来。
  - 速度三档：慢步 / 小跑 / 疾驰（耗马力）。
  - **马上战斗**：左右挥砍（简化连段）、冲锋撞飞（低速时撞开杂兵，高速时击飞）。
  - 马有体力与受惊；在千人战中马战是割草的另一种形态（冲阵）。
- **快速旅行**：驿站之间，需付钱；战役中不可用。

### 4.2 遭遇与事件系统（P2 的实现）

```
EventDirector（每 2 s tick）
 ├─ 根据玩家位置、区域控制值、时间、天气 → 计算候选事件池
 ├─ 冷却 & 密度控制：同屏最多 1 个主动事件、2 个环境事件
 └─ 生成 → 事件实例（状态机：预告 → 进行 → 结算 → 后果写回世界）
```

**事件模板（首批 12 个）**

| 事件 | 规模 | 触发 | 后果 |
|---|---|---|---|
| 商队遇劫 | 10–20 | 官道附近 | 救下：钱+声望；不救：该路段物价上涨 |
| 村庄被劫 | 20–40 | 村庄控制值低 | 救下：村庄繁荣；失败：村庄荒废数日 |
| 敌军巡逻 | 6–12 | 敌控区 | 可绕开/伏击/硬刚 |
| 伏兵 | 15–30 | 峡谷/松林 | 从两侧杀出 |
| 押送俘虏 | 8–15 | 随机路段 | 解救后俘虏成为援军 |
| 流寇营火 | 5–10 | 夜晚 | 偷袭有加成 |
| 敌将游猎 | 1 将 + 10 | 低概率 | 单挑，掉落武将装备 |
| 求援信使 | — | 据点被攻 | 限时赶到可守住据点 |
| 野兽 | 1–5 | 山林 | 狼群、熊 |
| 古墓探秘 | — | 兴趣点 | 小解谜 + 奖励 |
| 决斗挑战 | 1v1 | 酒肆/集市 | 纯手感考验 |
| 战场余烬 | — | 战役后 | 拾取、遇散兵 |

### 4.3 战役（P3：割草是高潮）

- **何时发生**：主线节点、区域控制值跨过阈值、玩家主动攻打关隘。
- **规模**：近战 170 个完整 AI + GPU 远景军阵 1000–3000（**直接复用现有三期成果**，远近交接已实现）。
- **结构**：战役开始 → 圈定战场（半径 150–250 m，雾墙/山形自然收拢）→ 阶段目标（守门、斩将、夺旗、救援）→ 敌将 → 结算并写回世界。
- **与开放世界的衔接**：不切场景、不加载画面；战役区域内导演切换为现有的 `updateDirector` 模式，结束后恢复世界导演。

### 4.4 战斗手感（M0 必修）

| 改动 | 当前 | 目标 |
|---|---|---|
| 同时出手敌兵 `MAX_TOKENS` | 2 | 遭遇 3、战役 5，带明显前摇提示 |
| 轻击顿帧/震屏 | 修 bug 后偏弱 | 按权重分档恢复，保留架势/破盾修正 |
| 技巧奖励 | 完美闪避、弹反奖励较小 | 弹反/完美闪避后 2 s「破势」：伤害 ×1.5、无双槽 +15 |
| 连击里程碑 | 无 | 50/100/200 连击：全屏特效 + 短时强化 |
| 机器人对照目标 | 技巧 +28% | 技巧 **+60% 以上** |

### 4.5 成长

- **武将等级**：经验来自战斗与事件，解锁新连段、无双技。
- **装备**：武器（刀/枪/戟/弓）、甲、马具；敌将游猎与战役掉落「名器」。
- **声望**：分势力；联军声望解锁援军与据点功能。
- **营地**（中期）：可升级的据点，招募随从。
- 沿用现有「将魂」跨局系统作为难度/新周目机制。

### 4.6 生活感（P1）

- **日程 AI**：村民按「日出耕作 → 午间集市 → 傍晚回家 → 夜间点灯」切换；商队按路线往返；巡逻按班次。
- **远处模拟降级**：玩家 300 m 外的 NPC 只做「数据层」推进（位置、状态），不渲染不跑动画。
- **环境细节**：炊烟、犬吠、旗帜随势力变色、战后的尸体与乌鸦、营火光。

### 4.7 昼夜与天气

- **昼夜**：一天 = 现实 24 分钟；太阳/月亮方向驱动现有级联阴影与大气后期。
- **天气**：晴、阴、雨、雾、沙尘；影响能见度、马速、弓兵命中、事件池（雾天伏兵概率↑）。
- 现有 `BattlefieldAtmosphere` 节点已有高度雾和体积光，可直接参数化。

## 5. 技术架构

### 5.1 工程结构（放开单文件后）

```
zhen-sanguowushuang/
├─ src/
│  ├─ core/        渲染器、后期、输入、时间、事件总线
│  ├─ world/       地形分块、植被、道路、水体、天空/天气
│  ├─ actors/      角色、骑马、AI、GPU 军阵
│  ├─ combat/      连段、判定、受击、无双（从现有文件拆出）
│  ├─ systems/     事件导演、势力、日程、存档、任务
│  └─ ui/          HUD、地图、对话、商店
├─ assets/
│  ├─ models/      glTF（角色、马、建筑、道具）
│  ├─ anims/       动画片段（glTF / 动捕重定向）
│  ├─ terrain/     高度图、生物群系图、道路样条
│  └─ audio/
├─ tools/          Blender 脚本、地形烘焙、资产打包
└─ demos/          现有竞技场版本保留
```

- 构建：**Vite**（ES 模块、资源哈希、开发热更）。
- 存档：`IndexedDB`（世界状态较大，localStorage 不够）。

### 5.2 渲染（WebGPU 为主，WebGL2 回退）

| 子系统 | 方案 | 复用现有 |
|---|---|---|
| 地形 | 64 m × 64 m 分块，四级 LOD（几何裁剪/CDLOD），GPU 采样高度图做法线 | — |
| 地形材质 | 生物群系权重图 + 4–8 层贴图混合（TSL） | 地面土壤/车辙着色 |
| 植被 | GPU 实例化 + 计算着色器做视锥剔除与距离 LOD；远处用公告板 | GPU 粒子的实例化管线 |
| 远景 | 2 km 外用低精度地形 + 天空雾融合 | 大气后期 |
| 阴影 | CSM 3 级 → 4 级，远级降分辨率 | `CSMShadowNode` |
| 人群 | 近战完整 AI + GPU 军阵 | 三期 GPU 军阵 + 远近交接 |
| 角色动画 | 骨骼动画烘焙进贴图（VAT），在 GPU 上播放，支持数百个动画角色 | 现有 21 骨骼 rig |
| 粒子 | 现有 13 万容量 GPU 粒子 + 双 pass 软粒子 | ✅ 直接复用 |

**性能预算（M1 Mac，1440×810，60 fps）**

| 项 | 预算 |
|---|---|
| CPU 逻辑 | ≤ 6 ms |
| GPU 帧 | ≤ 12 ms |
| 绘制调用 | ≤ 400 |
| 三角形 | ≤ 600 万 |
| 显存 | ≤ 1.5 GB |
| 首屏加载 | ≤ 8 s（之后流式加载） |

### 5.3 流式加载

- 以玩家为中心 3×3 地形块全精度、5×5 中精度、更远只留最低 LOD。
- 地点（村庄、营寨）作为独立资源包，进入 400 m 范围时异步加载，离开 600 m 卸载。
- 使用 `Worker` 解码几何与生成植被实例，避免主线程卡顿。

### 5.4 资产来源（放开约束后的选择）

| 类别 | 首选 | 备选 |
|---|---|---|
| 角色 | 开源/CC0 人形 glTF + 自研 Blender 管线改装（甲胄、头盔、旗） | AI 生成后人工修 |
| 动画 | Mixamo 等动捕库重定向到现有 21 骨骼 | 现有手写关键帧作为兜底 |
| 马 | CC0 马模型 + 行走/小跑/疾驰循环 | — |
| 建筑 | Blender 程序化（模块化墙、屋顶、城楼）| 现有关楼代码迁移 |
| 地形 | 程序化（噪声 + 侵蚀）烘焙高度图，手工修关键区域 | 真实 DEM 艺术化处理 |
| 音频 | 现有 WebAudio 合成 + 少量采样（马蹄、环境声） | — |

## 6. 里程碑

| 阶段 | 目标 | 关键交付 | 验收标准 |
|---|---|---|---|
| **M0 手感修复** | 让战斗本身好玩 | 出手上限、打击感、技巧奖励、连击里程碑 | 机器人对照技巧收益 ≥ +60%；试玩主观「爽」 |
| **M1 世界原型** | 验证「骑马逛 + 遭遇」比竞技场好玩 | 1 km² 起伏地形、骑马、1 个村庄、2 种遭遇事件、昼夜 | 10 分钟试玩里主动去找了事件；60 fps |
| **M2 世界底座** | 能撑起 4 km² | 分块地形与 LOD、植被、道路、天气、流式加载、存档 | 横穿地图无卡顿；内存稳定 |
| **M3 世界内容** | 有东西可玩 | 4 个区域、城池、据点占领、12 个事件、势力系统 | 1 小时游玩内容不重复 |
| **M4 战役融合** | 割草回到高潮位置 | 虎牢关战役在开放世界中原地触发，接千人军阵 | 战役进出无加载；同屏 ≥ 1000 |
| **M5 生活感与叙事** | 像一个活的世界 | 日程 AI、商店/任务、主线第一章 | 外部试玩反馈 |

**建议节奏**：每个里程碑结束都打一个可玩版本、跑验收脚本、让你试玩后再进入下一个。**M1 是生死关**：如果原型证明「骑马逛 + 遭遇」并不比竞技场好玩，就回到 M0 的方向深挖竞技场玩法，而不是继续堆世界。

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 世界大但空 | 最致命：玩家赶路无聊 | P2 密度指标（每 60–90 s 一个事件）写进验收；M1 就测 |
| 浏览器性能/显存 | 掉帧、崩溃 | 严格预算、LOD、流式；WebGL2 回退版降规格 |
| 资产风格不统一 | 不像一个游戏 | 统一 Blender 后处理管线（配色、甲胄套件、描边/轮廓光材质） |
| 动画质量 | 角色像机器人 | 尽早引入动捕重定向；VAT 烘焙 |
| 工作量失控 | 永远做不完 | 每个里程碑可独立发布；先做窄而深，再扩宽 |
| Safari/移动端 | 兼容性 | 明确首发目标为桌面 Chrome/Edge；Safari 走 WebGL2 回退 |

## 9. 待你拍板的问题

1. **首张地图**：虎牢关—洛阳（与现有剧情衔接）还是换一个更开阔的地区（如长坂坡、赤壁）？
2. **主角**：只有赵云，还是可选多名武将？
3. **骑马的比重**：马是交通工具为主，还是马战作为核心战斗方式之一？
4. **叙事深度**：以事件和沙盒为主，还是要有完整的主线剧情与过场？
5. **M0 是否先做**：建议先花一轮修战斗手感，再开 M1。
